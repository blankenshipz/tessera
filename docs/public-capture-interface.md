# Approved normalized public capture and private outbox (source-only v1)

This is **not** a V2 public-event parser or installed runtime binding. The available
runtime `V2Harness.status` returns usage/outcome only. The V1 live adapter handles
`type`, `properties.sessionID` and `{info,parts}` readback, but that is not a
documented V2 public-visibility guarantee. This source lane deliberately does not
parse that raw stream, persist prompts/tool bodies, or count private reasoning.
Default tests are isolated fixtures, including a mocked HTTP transport to the real
client implementation. They prove no generated reasoning or live capture.

## APIs and trust boundary

For new ordinary runtime input, use the [separate curated input/policy contract](separated-capture-contexts.md).
The legacy one-context policy shape below is preserved for historical records, not
an instruction to feed public-capture JSON into the model as curated input.

`tessera_control.public_capture` provides:

- `CaptureBinding`: strict `tessera-public-capture-binding-v1`. It carries opaque
  org/project/actor/credential/context/run/session/harness-instance/model/task IDs,
  `destination_digest` (`sha256:<64 lowercase hex>`), immutable context/skill/config
  digests (64 lowercase hex) and the human-approved allowed public event list.
  It contains no token, URL, prompt or account value. Load these pins from trusted
  admission, never an unauthenticated caller or runtime's `public=true` assertion.
- `PublicObservation`: strict `tessera-normalized-public-observation-v1`, inheriting
  the existing `PublicHarnessMetadata` sequence/watermark/capture-state/gap bounds.
  Adds `model_id`, closed observational `outcome`, optional opaque `message_id`,
  `tool_id`, `operation_id`, `registered_output_id`. No arbitrary payload or extra
  field is accepted. Categories are message/tool/permission/delegation/generated_output.
  Messages require upstream message IDs; tools require non-human tool IDs.
  Permission and delegation records are observations, never approval authority.
- `PublicCaptureAdapter(binding, disclosure_resolver, output_resolver=None)` and
  `.envelope(observation)`: produce the existing `AppendAgentProvenance` envelope,
  bounded to 16 KiB. Every run/session/task/model/context/skill/config pin must match.
  Stable record IDs derive from org/project/credential/run/source-event identity;
  source sequence is supplied by the approved metadata producer, never assigned by
  counting raw/private parts. `source_watermark` describes the eligible public stream
  only. Unknown/private/unsupported raw schemas fail before any journal write and
  do not automatically manufacture a public event or source gap. If known eligible
  public metadata is missing, the trusted producer supplies explicit bounded gaps.

`disclosure_resolver(binding)` is an injected **trusted authenticated registry
reader**, not an HTTP request field or a proof generated by the adapter. It must
verify the actual immutable human-issued context and current disclosure fences,
and return only `context_id`, `org_id`, `project_id`, `credential_id`,
`destination_digest`, `issuer_role='human'`, `disclosure_approved=True`, classification
public/project and `body` containing strict `PublicHarnessDisclosure` JSON. IDs and
policy must exactly match binding. It is rechecked on capture and delivery. A
missing/withdrawn/expired resolver handoff blocks capture/send; exceptions are not
persisted or printed. Matching pins do not independently prove harness installation.

### Research output references are not worker manifests

`RegisteredPublicOutputReference` is a strict metadata-only readback from
`output_resolver(registered_output_id,binding)`: `output_id`, actual `artifact_id`,
`family:generated_public_research_output_v1`, `output_kind`, actual
`writer_actor_id`/`writer_credential_id`/`writer_org_id`, current `disclosure_id`, exact
`CaptureBinding`, `source_event_id`, `source_sequence`, optional `operation_id`,
`sha256`. The trusted resolver must verify real registration, human output admission,
current tenant/credential/destination disclosure and artifact integrity. Producer
claims or byte content are not a substitute. Source ID/sequence, binding, output ID
and operation must match the observation. The artifact alias must equal the registered
output ID; it is not an entry in the worker `artifacts` table. Envelope links use
the distinct `record.generated_output` shape below, context and nullable task/operation
references, and the registered digest; there is **no** fabricated
Kubernetes Job/output manifest or worker `output_proof`.

**Schema53 source integration:** collector now validates against the actual immutable
`generated_public_outputs`, current human admission and recipient disclosure ledgers
in the caller's transaction, including idempotent replay. Notebook records and
`generated_output.registered` events join the same current snapshot. Test fixture
bytes/public observations remain synthetic; their registration/collector/client/
SQLite joins are real local components, not model inference or live V2 capture.

Authoritative wire contract: optional `AgentProvenanceRecord.generated_output` is
strict `GeneratedResearchOutputReference` with **only** `family`, `output_id`,
`disclosure_id`, `sha256` (64 lowercase hex), `output_kind` (planner_proposal or
critic_review), `writer_actor_id`, `writer_credential_id`, `writer_org_id`. Absent
generated fields are omitted, preserving historical schema52 worker envelope hashes
and ACK shapes. The generated family may not carry worker `artifact_id`, manifest,
Job UID, attempt, execution permission, bounded-agent grant or consumption references
or a worker `output_proof`. `kind=attempt` remains an observational label, not proof
of an admitted experiment. The real output author is required for append, including
its own independent human output disclosure: authorship is not disclosure authority.
The record's model/harness/source/hex digests must exactly match backend registration.
`task_id` may be null only for generated research capture; non-output public events
still require a real central task. No task/operation/lease is invented for reasoning.

Recipient notebook access retains explicit notebook:read plus context:read and the
current human output disclosure for that exact enrolled recipient/destination.
Human projection is a separately authenticated path. Revoked/expired output admission
blocks append/replay but preserves retained history; current disclosure controls
history projection just as backend read does. Revoked/expired recipient disclosure
withholds output hashes/references and marks permission-filtered completeness.
Projected `output.recipient_disclosure_id` reports the viewer's actual currently
valid disclosure (null on the separate human path), not the author's append receipt
disclosure. The latter remains historical metadata in `record.generated_output` and
does not confer access or transfer authority to a recipient.
Raw bytes and hidden reasoning are never in collector/projection/outbox records.

## Dedicated durable journal

### Optional guard phase observations (source-only, non-admitting)

`record.guard_phase` is optional `GuardPhaseObservation`:
`protocol:tessera-provenance-guard-phase-v1`, existing typed `phase`
(`opencode-model-hook-phase-v1`), nullable existing `owner_checks`
(`tessera-owner-guard-checks-v1`), and fixed false admission/production/consumption
qualifiers, unknown financial freshness and explicit unsigned-reference proof limit.
It is omitted when absent; legacy envelope/ACK/binding/policy digests remain unchanged.

Use public category `guard_phase`, `kind:model`, `outcome:unknown`, an actual project
task and the separately human-issued input/policy contract. Policy must allow the
category and include `guard_phase_binding:PublicGuardPhaseBinding`: approved issuer
HTTPS origin, opaque enrollment/adapter/nonce/session/proof SHA256 refs, exact
order revision/sequence/model and provider/model/tool structural hashes. Optional
owner origin/publisher-ref expectations must be supplied together. They are approved
expectations, not authenticated receipt origin or actual guard execution proof.
Existing run/session/instance/context/skill/config pins and current principal/tenant/
destination/disclosure fences remain enforced. Policy cannot issue execution authority.

`guard_observation_from_report(CorePhaseReport|JoinedGuardEvidence)` is the small
port from the existing supplied observer report to this typed field. It invokes no
callback, guard, inference or authentication. The approved `PublicCaptureAdapter`
also accepts the typed field on `PublicObservation`; its existing private outbox and
enrolled collector client carry the unchanged envelope/idempotency interfaces.
Actual SDK authority and owner-publisher integration still need genuine approved
embedding adapters; JSON `authorized:true`/proof claims are rejected, not trusted.

Append and idempotent replay require fresh phase/owner execution/quota observations:
strict aware timestamps, no future time, maximum 30-second phase/owner/quota windows,
native snapshot age <=30 seconds and no expiry beyond snapshot+30. Core fingerprints,
challenge/session/proof/order and model must match policy; supplied owner receipts
must independently match approved publisher expectations and that same phase.
Unavailable quota without a snapshot and absent owner checks remain explicit unknown
facts. Denied/failed/unknown owner outcomes remain observations, never successful
admission or model-generation results. A nonce cannot be rekeyed as a second record;
changed receipt content conflicts. Expired retransmissions stay unacknowledged rather
than pretending old evidence is current. Record/event/idempotency writes stay atomic
in the existing ledger; no new tables/migrations or attestation platform were added.

Notebook `guard_observation` displays source observed/valid-until and backend recorded
times, stage/finality/order limits, `freshness_at_export` (within_reported_window or
expired), evidence classes, financial/provider unknowns and missing owner facts.
Every projection remains `complete:false`, non-admitting and unverified. Older
financial `verified_at` is preserved, not made fresh. Serialized refs do not establish
origin, live SDK consumption, private guard execution or final transport. Current
capture credential/context disclosure is rechecked for agent viewers; undisclosed
peers get a withheld marker. Human projection remains separately authenticated.
No guard bodies, prompts/tool content, auth/account IDs or raw stream are accepted.

The [guard evidence contract decision](guard-evidence-contract-decision.md) remains
proposed, not approved. Genuine SDK enrollment/principal scope, actual sanitized
owner publisher, root semantic/admission review and installed/live acceptance are
still prerequisites. Tests use actual temporary collector/HTTP/SQLite/outbox with
synthetic phase/owner receipts; they are not proof that the private guard ran.

`PublicCaptureOutbox(directory, adapter, capacity=10000)` uses a separate
`public-capture.sqlite3` file, private owned directory (0700), regular owned file
(0600), refuses symlinks/non-private existing DB/SQLite sidecars, and uses SQLite
DELETE journal plus FULL synchronous writes. It does not touch the control database
or schema version. Private schema version **1** is stored in `capture_meta` with
immutable binding; reopening cannot replace enrollment/run/session/config pins.
`capture_events` stores only canonical envelopes, stable source IDs/sequences,
source watermarks, gap/unknown flags and closed delivery state/counters/sequence.
No credential, auth header, raw event/exception/response or tool text is retained.
Capacity is bounded 1..10000 records; full capacity is an explicit capture failure,
not successful completion or implicit sequence advancement.

- `.capture(observation)` atomically inserts source ID and sequence once. Exact
  duplicate returns the same record ID; rekeyed sequence/event or changed envelope
  conflicts. Out-of-order eligible public delivery is allowed; missing sequences
  are never silently filled. Restart preserves envelope/key and delivery uncertainty.
- `.deliver_next(client)` makes **one** attempt for the lowest unacknowledged source
  event, including prior failed/unknown delivery; no autonomous retries or sleeps.
  Reuses the unchanged `ProvenanceClient.append(project_id,record,grant_proof,
  idempotency_key)` interface and identical `provenance-<SHA256(record_id)>` key.
  Configure the supplied client with its exact expected enrollment actor pins and
  existing secure runtime credentials; this module does not discover credentials or
  start services. It rejects any envelope needing an unsupported worker output proof
  rather than stripping it. Before network crossing it commits `unknown` and increments
  attempt count. A crash after acceptance is safely redelivered with the same key.
- ACK normalization accepts only the exact validated client `DeliveryResult` shape,
  same record ID, accepted/collector_acknowledged, HTTP 200/201 and a strict positive
  integer collector sequence. Strings, booleans, extra/raw data, mismatched IDs or
  unspecified outcomes remain unknown. Collector 3xx/4xx rejection is `send_failed`;
  transport/client exceptions and unrecognized responses remain `unknown`. Neither
  advances acknowledgement. Client itself validates raw ACK envelope and actor;
  normalization is not independent server authentication or raw HTTP verification.
- `.watermarks()` separates reported source watermark/captured count from accepted
  count and **contiguous acknowledged source prefix**. Missing events, declared gaps,
  unknown capture, pending, send-failed and unknown delivery counts remain explicit.
  It makes no complete-transcript/source-visibility/scientific-validity claim.
- `.close()` closes the journal. Keep the journal through active-run restarts; do
  not replace it with a new run/session to hide unresolved delivery or capture gaps.

1. `src/tessera_agent/remote_reasoning_runtime.py:V2Harness.status` needs an actual
   supported V2 public metadata/readback binding, distinct from usage tokens and
   outcome. Its current return value does not expose eligible messages/tool events.

   around `self.harness.status(row)` and before terminal-state completion, must hand
   eligible approved normalized observations to `.capture`; drain via the existing
   enrolled client after fences and preserve journal/binding through restart. Do not
   feed prompt text or usage reasoning-token counts into this adapter as events.
3. Runtime owner supplies authenticated human disclosure/output-reference resolvers
   backed by the actual metadata lookup. Schema-53 registry and source-54 typed
   A2A/provenance joins now have local HTTP/SQLite evidence, including recipient
   records and ACK handling with synthetic model bytes. This does not connect V2
   public event extraction or `ReasoningSupervisor.tick` to capture/drain, nor prove
   an independently running generated critic/consumer. No runtime/profile/agent
   integration is inferred from these source fixtures; the prior runtime write
   denial is not retried or bypassed.
4. Parent performs real public-visibility/schema validation and the installed
   planner/critic/notebook/restart/cancel journey. Source fixture tests do not satisfy
   those live checks. Missing exact V2 schema is an implementation gap, not permanent
   permission denial or authorization to invent a parser.
