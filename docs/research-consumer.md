## Implemented component interfaces

- `research_consumer_store.ResearchConsumerStore` reuses the private owned runtime
  journal, immutable run/session binding and durable SQLite transactions. It adds
  research stage, source/output reference and effect ledgers. Effect IDs and payload
  digests commit **before** external calls. No prompt, generated bytes, tool body or
  upstream exception is stored. Exact arguments are reconstructed from the same
  immutable admitted inputs/central public output and checked against that digest;
  changed payloads cannot reuse a boundary. A lost ACK remains unknown. Explicit
  reconciliation is for an identical idempotent registry/tool/peer request, never
  another model prompt or session. Store retains one boundary per mutation; it is
  not an autonomous multi-experiment scheduler.
- `ResearchConsumer` binds a human-admitted role, public-capture binding, exact
  output-registration grant/revision and existing harness-binding manifest. Before
  effects it invokes `verify_binding` on fresh installed observation ports, checks
  actual principal/instance/model, fetches the current scoped curated context and
  hashes its body, checks the original runtime session and supervisor fences.
  Only manifest-permitted named MCP tools are callable. No default synthetic
  adapter or owner identity exists. Synthetic observation ports are test evidence
  only, not authentication or installed-harness proof.
- `tick` resumes the existing supervisor/session and registers the final output
  through `tessera_register_generated_output`. It validates source/digest/pins and
  actual writer attribution in the registry ACK. Registration is distinct from
  inference permission. Current human output disclosure remains necessary even
  for the author. Unknown registration blocks; an explicit same-key reconciliation
  does not prompt the completed session again.
- `capture(author_disclosure_id)` reads actual registry metadata, passes an approved
  generated-output observation into `PublicCaptureOutbox`, and attempts one bounded
  collector delivery. It requires trusted authenticated human-policy/output
  resolvers from `capture_factory`; it does not invent them. Coverage is **unknown**
  for the full interaction stream: this projection observes final output only.
- `propose` reads separately disclosed public bytes, validates `AgentPlan`, submits
  an immutable MCP task-plan proposal and requests human review. Grant consumption
  requires an actual backend proposal promotion plus a matching grant task binding,
  not generated approval text or a caller boolean. Critic cannot dispatch. Existing
  closed MCP consumption schemas/backend fences govern admit/dispatch/status/cancel;
  no Docker execution or broader command support is fabricated. Observation and
  notebook methods retain caller-attribution and authorization semantics.
- `deliver_critic` freezes author-capture ACK/output pins and uses stable A2A
  submit/result message IDs with the same task. `consume_critic` reads the peer
  task, fetches and validates registered bytes with the planner's own disclosure,
  then sends an explicit same-task consume ACK. This reports authenticated read
  and acknowledgement, not model understanding. These methods still require an
  admitted genuine peer port; source availability does not prove independent peers.
- `ResearchPeer` is a bounded A2A 1.0 JSON-RPC HTTP client for existing official SDK
  routes. It rejects redirects/errors/mismatched request IDs, caps readback at
  256 KiB, and never transmits raw output text. The historical reference-only path
  remains unchanged. Consumer requires the new research-generated family and paired
  actual author capture record/sequence; no worker manifest is substituted.
- `PublicStatusCapture` is called by `ReasoningSupervisor.tick` after authenticated
  status/usage/fence checks and before terminal completion. It accepts at most eight
  normalized eligible observations, verifies run/session identity, captures and
  drains through the existing outbox/client, then the supervisor fences again.
  Unsupported source/schema or uncertain capture halts instead of marking model
  completion. Default supervisor paths have no implicit capture producer.

Consumer guards require at most **3 steps / 120 seconds / 8192 observed tokens**.
These are observed soft guards, not hard pre-token billing guarantees. Existing
expiry/revocation/stop/usage enforcement and uncertain termination semantics remain.

## Orchestration and pending installed ports

`ResearchJourney` journals role/run/session bindings and immutable output, peer,
proposal, human review, attempt, operation and consumption references before
effects. Each poll advances at most one stage. The ordered source path is initial
planner registration/disclosure → independently curated critic context/output →
actual peer delivery → planner read/ACK → **explicit same-session planner prompt**
→ fresh continuation registration/disclosure → proposal/review request → separate
human decision plus backend promotion → issued admission/dispatch grants → current
attempt status → observation/notebook/export. ACK is not model understanding.

Unknown prompts are held without replay or a new session. Exact authenticated
session/message/prompt-digest readback is required for reconciliation. Unknown
typed cancellation uses an explicit same-command/same-key reconciliation, never
automatic replay. Cancellation ACK leaves `cancel_requested` until authenticated
status reports actual terminal experiment state; it does not establish model
provider termination. Human rejection is bound to the submitted proposal.

The CLI accepts secret-free private references for distinct principals, credentials,
role contexts, policies, model, binding/config/skill files, dedicated authenticated
harness origins, observer admissions and output grants. No API-key route, arbitrary
factory module, default coding service or paid fallback is provided. These are
references, not proof; construction must validate actual installed observations.

Available production wiring in `research_factory.py` and `research_transports.py`:
owned private state with a nonblocking single-journey lease; rotating authenticated
HTTP references; verified TLS/explicit CA trust; a real SDK stdio session launched
with a fixed installed Python module and only runtime **reference** environment
fields; enrolled A2A clients; supervisor; actual MCP registry/proposal/review calls;
split-context capture adapter, normalized producer and private outbox; authenticated
approval polling and notebook stages. No arbitrary executable/module or credential
value is accepted in configuration. Source profile bounds remain ≤3 steps, 120
seconds and 8192 observed tokens. TLS verification cannot be disabled.

Fresh final collection now uses a bounded actual session-message page to read the
exact admitted user-message ID/body digest, reject a later user turn or ambiguous
ordering, and project only a completed assistant created after that prompt. The
first finished assistant is never reused for the second prompt. The approved phase
number is not a fabricated full-public-stream sequence/watermark. The continuation
prompt message/digest and final source cursor survive journal restart.
