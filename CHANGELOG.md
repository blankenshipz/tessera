# Changelog

Tessera remains a developer alpha. Git history records source changes; this page
does not create release tags, a supported binary release or compatibility promises.

## Unreleased

- Salad campaign executor: a `source_revision` the live check would refuse (a bare commit without `+sha256:<installed source digest>`, a malformed pin or one whose digest is not the installed source's) used to load and then stop every route at the live-check start with no receipt. The executor config loader now refuses it at start with the live check's own check (shared `salad_live_check.is_source_pin` / `installed_source_pin`), and `tessera deploy-check --apply refresh_source_pin --source-commit <40hex>` (also run by `deploy-upgrade` when the plan names `source_revision`, including for a legacy bare commit or malformed pin; any other executor config error, alone or alongside a pin problem, still blocks the upgrade) rewrites the pin from the installed source in place, atomically, keeping the file mode, with a receipt; an unmeasurable source is refused. Run from a repository checkout, the command also refuses a `--source-commit` that is not the checkout head, before any fix (the commit is otherwise operator-asserted; only the digest is measured). No schema change.
- Reasoning supervisor (ADR 0119 amendment): a completed one-shot run exits 0 and its manual unit goes inactive instead of failed. A start whose run identity is already closed runs nothing (no harness, control-plane, grant, ledger or model call), logs `run <id> already closed (state ...)` and exits 0 when that run completed (2 otherwise), so a restart can no longer loop into the start limit. Exit codes are distinct: 0 completed, 1 crash (the only one the unit restarts), 2 fenced or stopped, 77 refused (supervisor already running, run identity bound to another profile), 78 configuration error; the unit sets `RestartPreventExitStatus=2 77 78`. The next run takes a fresh run identity from the request: `run --run-id ID`, or `tessera reasoning install --apply --new-run` (a generated `run_id` bound to the installed prompt). No fence changes; no schema change.
- Execution limits (ADR 0171): a project's `max_concurrency` is bounded by an operator ceiling, `TESSERA_MAX_PROJECT_CONCURRENCY` (default 8, at most 64), instead of a fixed 8, so an operator can give a project with stuck grants room to admit a new campaign. Only the control environment sets it; no API field, MCP tool, spec or campaign input raises it. A malformed or out-of-range value stops startup. A request above the ceiling is refused with 422; a stored limit above a lowered ceiling admits new grants only up to the ceiling. `execution.limits_configured` records `concurrency_ceiling` only when the operator set it, so default events and responses are unchanged. Schema 89 rebuilds `execution_project_limits` with a CHECK of 1 to 64.
- Exited without a report (ADR 0158, proposed): a stage watcher `failed` report now carries an optional closed `exit` (`exit_code`, `oom_killed`), but only when its probe read the container as definitively exited. If the executor's exit observation and run receipt never reach control, the runner closes such an `admitted` or `running` attempt on a non-billable worker grant as `failed_transient` / `exited_without_report` (never permanent on the watcher's word), with exit class `killed`, `oom` or `error`, settled at zero and with its grant and slot released, after `exit_report_grace_seconds` (default 300, at most 900). It does so only when the report's lease and epoch match the operation, every lease has expired, and there is no confirmed exit, receipt, later observation or arriving upload. The close is fenced on the grant revision like ADR 0053, late reports are refused, and the retry policy applies. No schema change.
- Worker: a stage the worker killed itself (failed lease renewal or heartbeat, or a lost provider receipt report) no longer leaves its attempt `running` and its grant holding the project's slot until the grant expires. Docker confirms the SIGKILL with exit code 137. That confirmed exit is now reported to control like any other, through the durable observation outbox (ADR 0054). Control then closes the attempt about 150 s later as `failed_transient`/`exit_confirmed_unresolved` with the exit code as evidence, releases the grant, and the retry policy applies (ADR 0053). If the report cannot be delivered, the run ends `report_pending` and the poller recovers and delivers it once. A cancel that is unconfirmed or has no integer exit code reports nothing new. An observation control refused is never reposted. No schema or control change.
- Salad live check: the pre-start settle read now leaves a closed reason on the receipt. A failed settle observe or heartbeat adds `prestart_settle_read` (`call` observe/keepalive, `reason` read_unavailable/conflict_state/timeout/other, `http_status_class` 2xx/3xx/4xx/5xx/none, `attempts`, `outcome` failed/recovered; no exception text, body, URL or header). A transient settle read (timeout, or a non-deterministic failed read with a 5xx or no status) is retried at most 3 attempts with 2 s and 4 s pauses inside the run deadline; a conflict, 3xx/4xx or deterministic failure is not retried. The last failure still fails closed before start (`group_unsettled`, status `inconclusive`). The field is absent when nothing failed, so other receipts are unchanged. No schema change.
- Salad group list (ADR 0031 addendum): a project with many stopped groups no longer blocks every create/start preflight with `malformed_response` (`request_kind` `list`). Salad documents no paging for the project group list (no query parameters, `items` with `maxItems: 100`, no page/total fields), so a list proves the reserved name absent only with fewer than 100 items and no pagination key; with 100 or more the preflight reads the exact name (a ProblemDetails 404 is absence, a 200 is the group, anything else fails closed). The list read alone accepts a 4 MiB body (other reads keep 64 KiB), since a few dozen full group objects can exceed 64 KiB. One list read serves the preflight and the guardian's lost-create read, whose automatic path still needs a complete list. No schema change.
- README gap residual pass: the README lists the campaign MCP tools once and in full, names `--agent-submission-kill-switch` next to `--agent-submissions`, and the platform, capability and documentation-guide docs say what is on main (grant poller, reasoning runtime, spend ledger, review jobs, delegations); the 5000 cent stage bound counts `retry.infra_retries`. Sandbox cleanup decides egress mode with the shared worker/control predicate, so a package with only one egress marker is refused instead of being treated as network-none. Tests pin the serve kill-switch refusal. No schema change.
- Agent authority (ADR 0155): a reasoning-only grant kind (`bounds.kind: "reasoning"`, actions `["model:call"]`, no execution binding) lets the agent loop make its first receipted model call without a running experiment. It needs a configured model-spend limit, its own budget of at least 1 cent and an expiry within 24 hours, is issued by a person (or the owner with an automation label) through the existing route, is debited by ADR 0142, and cannot consume, delegate, parent runtime bindings or affect any execution. The model-host egress limit stays with the model destinations and the egress allowlist. Grants without a `kind` are unchanged. No schema change.
- Receipts record the runtime image an attempt was granted: each attempt gains `image_provenance` (`image_ref`, `image_digest`, `base_images` from an image-build plan, `compressed_size_bytes`, and a closed `size_reason` of `adapter_cannot_read_manifest` or `size_unavailable` when the size is null), written as one `campaign.image_provenance` event at grant time. A provider may supply the size through an optional `image_pull_size_bytes` hook (the Salad provider accepts an operator-supplied manifest reader); it is read outside the transaction and never affects admission. Digest pinning is unchanged. No schema change.
- Image pull-size preflight: a provider may state `max_image_pull_bytes` (default off for `local-docker` and self-hosted providers, 4 GiB for a Salad campaign profile) and `strict_image_pull`. An image over the ceiling records an `image_pull_preflight` section (reason `image_pull_over_limit`, integer size and limit) in the campaign status and the receipt, and the spec dry run (`campaign-specs/validate`) shows it per candidate provider before dispatch; an unknown size records `image_size_unknown` and is never refused; a strict provider refuses with the new permanent placement reason `image_pull_refused`, after any trust or licence refusal (which a single-provider stage still reports as `input_not_admitted`). Salad profiles may record `image_pull_sizes` by image digest. No schema change.
- Salad (ADR 0149): a run whose allocation changed no longer always ends with its campaign blocked and its hold held. After the guardian stops such a route, the campaign executor reads the group through the route (one `observe` every `termination_poll_seconds`, default 15) until the provider's own read confirms it stopped with no instance, for at most `termination_confirm_seconds` (default 600, at most 3600). Only that recorded provider read confirms (never the guardian's status or a worker report); control re-checks it, scoped to the campaign's tenant, and the attempt ends `failed` and settles through the usual charge or reconcile path, after which the campaign's input release is revoked as usual. Unconfirmed at the bound, the attempt stays `unknown` and held with waiting reason `termination_unconfirmed` (or `termination_unconfirmed_new_allocation`) and one `campaign.salad_termination_unconfirmed` event; the receipt carries `salad_termination`. Route fences are unchanged. No schema change.
- Termination evidence (ADR 0160): a grant the development poller stopped driving without a confirmed exit no longer stays pinned. The poller inspects the exact container and reports, as the worker that held the lease, a confirmed exit with its exit code (for example 137 after a SIGKILL), or a confirmed exit with `termination_evidence: container_absent` when the container id control recorded for that lease no longer exists and the lease has ended (control re-checks both). The Salad campaign executor reports the guardian's confirmed stop of the route's exact group (`termination_evidence: provider_group_stopped`, matched by control to the route's recorded group; the guardian status now names the group it is about). The existing `/execution-grants/{id}/reconcile` route and the confirmed-exit resolution (ADR 0053, also for stuck campaigns under ADR 0153) then settle the grant and the stage's retry applies. Any doubt (no recorded identity, another container, a container that may still run, Docker or the guardian not answering) holds the grant with a reason in the grant's local `termination-evidence.json` or the executor log. Nothing is started, killed or charged by it. No schema change.
- Campaigns (ADR 0167): a paused campaign (steering pause or delegation lapsed) gives back a grant no worker ever took, live or expired, so it stops holding a project concurrency slot. The attempt is settled at zero as `not_started` and uses no scientific retry; a grant with any lease or operation is kept. Resuming re-acquires through normal admission and cannot exceed the limit. Waiters for project slots are now served first come, first served (`campaign.stage_waiting_limits` carries `attempt_id`), and the release and re-acquire are recorded as `campaign.slot_freed` (`paused_unleased_grant`), `execution.paused_unleased_grant_released` and `campaign.slot_reacquired` events. No schema change.
- Campaigns (ADR 0153): a blocked or paused campaign's grants that a worker already leased are driven through the existing evidence paths instead of waiting for a person. Once such a grant has expired, the runner classifies its attempt from control-plane records exactly as a running campaign's observation would, then applies the confirmed-exit resolution (ADR 0053) and the not-started auto-reconcile (ADR 0046) with their own accounting; a freed slot is recorded as `campaign.slot_freed` (new reason `confirmed_exit`). A leased grant no evidence settles keeps its project slot and hold and gets one `campaign.slot_held` event per attempt per spell (reason `leased_grant_unconfirmed` or `exited_awaiting_collection`, with a summary of leases, operations, observation and receipt, and the action a person takes). A live grant is never touched; nothing is started, cancelled or re-run and no lease is issued. No schema change.
- Campaign runner (ADR 0153): the reconcile sweep that frees releases and provider slots held by idle campaigns now pages with a cursor and wraps around, so 50 or more stuck idle campaigns can no longer starve later ones. No schema change.
- Campaigns (ADR 0153): a blocked or paused campaign no longer keeps the project concurrency slot or a worker's placement slot with capacity it provably is not using, so a new campaign is admitted instead of waiting until a person cancels the stuck one. An expired grant that no worker ever leased and that has no operation is reconciled at zero with the same evidence and accounting as the expired-unattempted reconcile route (the attempt ends `failed_transient`/`t1_grant_expired_unleased`); the not-started auto-reconcile (ADR 0046) now also runs for a paused campaign; and an attempt placed on a candidate provider that never asked for its grant stops counting while its campaign is blocked, paused or terminal. A live grant, or a claimed grant with no confirmed exit, keeps its slot (a person reconciles it). A resumed campaign gets capacity only through the normal grant checks, so it never double-runs. Each freed counter writes a `campaign.slot_freed` event (stage, attempt, provider, reason, campaign status, trigger, grant). No schema change.
- Campaigns: an input release held by a campaign that became terminal, blocked or paused no longer locks the same snapshot out of a fresh campaign until it expires. The release is revoked in the same transaction as the state change when no attempt of any campaign still uses it (in flight, `unknown` or unsettled) and no grant against it is unresolved, with a `campaign.release_freed` event (released by the system, trigger, campaign status, campaign id, snapshot digest); a bounded sweep on every runner tick frees releases of campaigns that went idle earlier. A refusal while the holder is live names the holding campaign and the release expiry (same organization only). No schema change.
- Salad GPU classes: `tessera providers gpu-classes`, `GET /admin/campaign-providers/salad-gpu-classes` and the MCP tool `tessera_list_salad_gpu_classes` (with the `provider_trust:read` tools) list the GPU classes the operator's Salad profiles allow, with the profiles naming each, the latest recorded hourly rate and recent allocation-instability counts from guardian records (pre-start re-binds, uncertain allocations). Names and any unrecorded rate or count are `null` with a `not_recorded` status, never invented or zero; the receipt read is read-only and an unreadable file or database fails closed. Read-only; no schema change.
- Delegated approval: a deferred campaign (`not_before`) whose start falls at or after the approval's expiry or the delegation's own expiry is no longer accepted and then stranded: the delegated approval is not recorded (409 `outside_delegation`, reasons `not_before_after_approval_expiry` / `not_before_after_delegation_expiry`), the campaign stays at its approval stop and the escalation is listed, matching a person's approval. Both paths share one comparison (`campaign_hold.not_before_reaches`). The stale delegation schema-version test no longer expects that migration to be the latest.
- Delegated Salad review stops (ADR 0150): an owner-signed delegation may carry an optional `review_rule` (review kinds, per-run cap no larger than the delegation's, time limit, provider classes, source-use outcomes; part of the terms digest only when present). A campaign with Salad stages inside it can then be approved under the delegation, and when the runner reaches a stage's review stop (after `not_before` for a deferred campaign) it records an ordinary exact-digest review pre-approval bound to that delegation, at the stage's own hold, and clears the source assessment, plan and source-use reviews without a person. Every use re-checks the delegation; anything outside it, a revoked or expired delegation or a signer no longer live stays stopped with reason codes (`campaign.preapproval_declined`, `delegation_declined` on the campaign view's `salad_review` item). The receipt's pre-approval entry names the delegation id and terms digest. A delegation without the rule behaves exactly as before. No schema change.
- Campaign re-approval (ADR 0045 amendment): a forward re-approval of a lapsed (`paused_delegation_lapsed`) campaign now re-checks admission in the approval transaction instead of resuming unchecked. The program budget must still admit the campaign's existing commitment (it is not counted twice), and the first approval's unlock requirements are re-evaluated and recorded (`Admission refused: program_budget_exhausted:<id>` / `unlock_not_satisfied:<index>:<code>`, 409, nothing written). A human re-approval of a conditionally admitted campaign must restate the first `unlock` exactly (matched by requirement digest; a missing, changed, added or stricter set is refused); a standing-started campaign reuses its standing approval's stored `unlock`. The receipt's `unlock` section lists every admission's evaluations, oldest first. Cleanup re-approvals are unchanged. No schema change.
- Agents no longer see who approved: the delegated-approval response (`POST /campaigns/{id}/delegated-approval`, `tessera_delegated_approve_campaign`) omits `approving_principal_id` from `approval` for an enrolled agent, and the live campaign view (`GET /campaigns/{id}`) omits it from `approval` and `approvals`, as the gate decisions already omit the decider. A person still gets the full row. The projection is applied to the response only, so the stored approval, the idempotency record and the receipt are unchanged. A guard test fails with the key path if an agent-facing response names an approver. No schema change.
- Tests: two README guardrails that had no test. `tests/test_single_run_no_retry.py` shows a second route for an operation that already has one (a recorded proposal event, a kubernetes dispatch row, or Salad's duplicate-group guard) is refused and writes nothing; `tests/test_stuck_detector_writes_only_findings.py` shows a stuck-campaign scan changes no table or event except its own findings and finding events and calls no cancel, approve, submit or runner entry point. No product change.
- Behaviour change for agent readers (audit O-05): `campaign:read` (and the `campaign:logs`, `artifact:read` and `budget:read` campaign views) no longer covers every campaign in the credential's project. An agent credential, enrolled or not, reads only the campaigns it submitted (recorded submitter, or the agent that consumed the owner's approved submission that started it); another agent's or a person's campaign returns the same 404 and message as a missing id. Project-wide reads hold only the caller's rows: campaign list and pages, window report and its counts, holdout claims, stuck findings (list, scan result, acknowledge), delegation decisions and escalations, standing-approval starts and triggers, and project-spend per-status totals. A delegation's `usage` totals are withheld from agents, an approved submission another agent consumed shows `campaign_withheld`, re-run links and the re-run tree appear only for readable campaigns, and an agent can no longer re-run a campaign it cannot read. Campaigns started by a standing approval are submitted by the approving person, so agents no longer read them. People keep organization-wide reads. No schema change.
- Tests: `tests/test_get_routes_do_not_mutate.py` calls every GET route of the control API (150 today, found by walking the included routers) as the owner, an enrolled agent and the fixture's worker and fails if any request commits to the database (a `PRAGMA data_version` watcher, then per-table digests), if a GET route appears that the test can neither exercise nor explicitly skip, or if a deliberately writing route goes unnoticed. No GET route writes today; no product change.
- Campaign comparison verifies the stored spec on read: `GET /campaigns/{id}/comparison` re-hashes the stored `spec_json` exactly as at submission and approval and refuses with `spec_digest_mismatch` when it no longer matches the digest the receipt names (an unparsable spec is `spec_unavailable`). What each arm declares now comes from the verified parsed spec. Other readers of `spec_json` are not changed by this.

- Approval delegation reads hide the signer from agents: `GET /projects/{id}/approval-delegations`, `GET /approval-delegations/{id}` (and its `decisions`) and `GET /approval-delegations/{id}/decisions`, read by an external-scope agent (and so the `tessera_list_approval_delegations` and `tessera_get_approval_delegation` tools), no longer return `created_by_principal_id`, `created_credential_id` or `revoked_by_principal_id` (the signer is the approver of a delegated approval), and decision rows drop `actor_principal_id` unless it is the reading agent's own id. Delegation id, terms, digest, state, usage and the decision outcome, reason, rule, evaluation, campaign, approval and gate ids stay. A person still reads full rows; `delegation-escalations` already returned no principal. Stored rows are unchanged. No schema change.
- Stage rejections: `_owns_lease` logs at debug level (no ids) when a worker step names a lease it does not own or when the ownership query itself fails, and tests pin that a failure to record a refusal event never turns a refusal into an allow and never changes the refusal or the foreign-lease 404 the caller sees. No behaviour change.
- Docs: the README's stage watcher sentence said the watcher is disabled by default and opt-in; since ADR 0125 it is on by default in the worker and the Salad executor (opt out with `--no-stage-watcher` or `enabled` false), and `docs/stage-watcher.md` now describes `--stage-watcher-stats` as the explicit enabled config it is. The observe-and-report-only guarantee is unchanged. No code change.
- Campaign comparison selection (ADR 0133): `GET /campaigns/{id}/comparison` takes an optional selection mode (`select_by` with `select_direction`) that chooses the best intervention arm on validation metrics only. Metrics and inputs are split into validation and test roles, held-out test metrics are reported only for the baseline and the selected arm, and a selection that would read test data, mix the roles, tie, or compare validation data against the test data is refused with a 409 reason code. Read-only; records nothing; no schema change.
- Campaign result comparison (ADR 0131): `GET /campaigns/{id}/comparison` (404 until terminal) compares named baseline and intervention stages of a campaign's terminal receipt, with repeatable `intervention`, `metric` and `evaluation_input` query parameters. Each arm needs exactly one succeeded attempt, every named evaluation input must have the same recorded identity in every arm, and the result is the recorded numbers and their deltas with no decision or verdict. Refusals are 409 with a stable reason code. The arms must also declare the same `gate_evidence.split_lock_id` and consume the same held-out input (`evaluation.holdout.input`) as recorded in the approved spec the receipt names, whether or not the caller named it (`split_lock_differs`, `evaluation_inputs_differ`, `spec_unavailable`). Read-only; no schema change.
- Salad guardian: an allocation change seen before any instance was observed running and before any custody began (no input fetched, no output written, no recovery) is re-bound to the new allocation instead of stopping the run, so a provider re-scheduling a container group while the image is still pulling no longer ends the run with `allocation_changed`. The re-bind never resets the deadline, the running window, the heartbeat or the billing clock, is bounded (`max_prestart_rebinds`, default 3, 0 disables, refused above 10) and stops as before once the bound is spent; once anything ran or any custody began a change still stops exactly as before, and a guardian that cannot tell stops. Re-binds appear on the guardian status and the run receipt (`guardian_prestart_rebinds`, reason `prestart_reallocation`). No schema change.
- Registry auth file check (ADR 0123): the worker's startup check and the CPU runtime's mount-time check now share one rule. The file is examined with `lstat` and must be a regular file (not a symlink) owned by the worker user, with a link count of 1 and no group or world permission bits; it is never read. A file with mode 0644 is now refused (use 0600 or 0400). A refusal carries one of a closed set of codes (`auth_file_unavailable`, `auth_file_symlink`, `auth_file_not_regular`, `auth_file_wrong_owner`, `auth_file_hardlinked`, `auth_file_group_or_world_access`). No schema change.
- Salad executor config: the `stage_watcher` block's `enabled` now defaults to true (it was required), matching the poller and ADR 0125: a block that only tunes a bound stays enabled with the default kill-switch marker, and `"enabled": false` still turns it off.
- Test scratch: `dev/pytest_parallel.py` and the focused-test runner (`tessera dev focused-tests`, `dev/focused_tests.py`) now put each run's pytest base directories under `.pytest-tmp/` with a per-run id, so concurrent runs never share one, and remove exactly the directories they created when every process is green (read-only trees are made writable first, symlinks are never followed, nothing outside `.pytest-tmp` is touched, and a cleanup problem never changes the exit code). A failing run keeps them and prints their paths; `--keep-basetemp` or `TESSERA_KEEP_BASETEMP=1` keeps them either way. They previously piled up without bound. No schema change.
- Storage retention (ADR 0094): a `test_scratch` class ages out the repository's `.pytest-tmp` (one basetemp per test run). Opt-in with `reclaim_test_scratch: true`; `test_scratch_max_age_hours` (default 24) and `test_scratch_root` (default `<repository>/.pytest-tmp`, must be named `.pytest-tmp`). It appears in `tessera retention plan` and `status`, keeps anything changed in the last hour, refuses symlinks and anything outside the root, makes read-only directories writable before removal, and removes only on a fresh plan digest. No schema change.
- Campaign receipts: readers trusted the stored `receipt_json` without checking it against its `receipt_digest`. Every reader (`GET /campaigns/{id}/receipt` and the MCP receipt tool, the campaign and window reports, `artifact`, `receipt_output` and `image_from` resolution, measurement gates) now loads the row through one helper that recomputes `canonical_digest` over the stored receipt and fails closed on a mismatch: a 409 with the stable code `receipt_digest_mismatch` (a gate refuses with `measurement_receipt_digest_mismatch`), nothing from the stored body returned. Valid receipts read unchanged. No schema change.
- Provider input tickets: Salad (and any provider the trust setting trusts with derived data) could only ever be issued input tickets for `public` snapshots; a `private_derived` input failed pre-start as `ticket_mint_failed` (Forbidden, "not approved for this local CPU authority") because the release check refused it before the provider-trust gate ran. Ticket issue and every pull now accept a `private_derived` release and leave the decision to the provider-trust gate (ADR 0040/0047): a route-less operation still receives `public` only and an untrusted provider is still refused. Licence labels (ADR 0113) are now also re-checked at ticket issue and every pull against the snapshot's own labels, so a provider whose trust entry restricts labels is refused restricted or unreadable labels (fail closed). No schema change.
- Sweep (nits, docs and test strength, no feature change): a Salad review whose decision request has already expired is no longer listed in `pending_human_approval` (an unparsable expiry is still listed, fail closed), and the `tessera_get_campaign` MCP docstring mentions the field; the registry auth file rule (private regular file, owner, link count 1, no group or world bits) is stated in ADR 0123 and its refusals are tested to carry neither the path nor the contents; `deploy-upgrade`'s private copy names the failing step (open, write, flush or close) and a close-time failure is now a copy-write error, not a misleading read error; `tessera service-credential` install and withdraw accept both `--owner` and `--owner-label`, and a newly created receipt file's directory is fsynced; the `_rename_noreplace` platform dispatch and real rename are tested.
- Provider-side fetch receipts say what the egress allowlist is (ADR 0097 amendment): the `public_fetch` object of a stage fetched on a non-local provider gains `egress_allowlist` (`hosts`, `declared: true`, `redirect_enforced: true`, `network_enforced: false`, and a statement that the provider's network does not restrict the stage to those hosts; Salad egress is provider-wide, ADR 0036). Bytes, seconds and cache are `provider_reported` only when validated fetched rows are recorded (`execution.public_fetch_recorded`, derived from retained output, never a worker claim), else `declared_only`. Contacted-host journaling is not recorded yet. Stages without pins and local-worker receipts are unchanged. No schema change.
- Heavy downloads run on the provider (ADR 0097, 0076, 0141 amendments): the Salad stage adapter carries a stage's `public_artifact` pins into the candidate (contract fetch rows and redirect hosts exactly the pins, inline manifest = image entry plus one pinned `file` item each, fetched and sha256-verified in the container before the claim), so a stage whose only reach is pinned public downloads can run on Salad and gets the ADR 0141 heavy candidate instead of being left local; its reviewable destinations are exactly the pin hosts. A new guard signal `large_public_inputs` counts the pins' `max_bytes`. Free-form `egress` is still refused (`egress_bound`), and any fetch row, redirect host or manifest item that is not a pin is refused (`public_artifact_contract_mismatch`). The runtime and launcher change (`/inputs-public` mapped to the fetched files), so the CPU image must be rebuilt; an older image refuses such a manifest before any fetch. No schema change.
- Heavy GPU stages get a Salad GPU candidate at submit (ADR 0141 amendment 2026-11-23): a `gpu`-tagged heavy stage was always recorded `gpu_candidate_unavailable`. A GPU Salad profile may now carry a `stage_adapter` section with the operator's `gpu_hour_usd` price (required there, refused on a CPU profile); with `heavy_remote_candidate` set (optional new `gpu_profile`), such a stage gets the adapter's GPU candidate on that profile as first alternate, estimated for its full duration at that price under the same operator/stage/campaign/program caps, and is tried first by the GPU-first ordering. A GPU stage is never offered a CPU profile (`no_gpu_profile`, `gpu_profile_unfit` otherwise) and a CPU stage never a GPU one. Admission still checks the published GPU rate; a local fallback keeps its ADR 0107 reason. Explicit adapter requests and CPU stages are unchanged. No schema change.
- Heavy-local audit on the operator surface and heavy refusals on the receipt (ADR 0107 and ADR 0141 amendments 2026-11-23c): `GET /projects/{project_id}/campaign-stuck/heavy-local-audit` and the MCP tool `tessera_heavy_local_audit` (read-only, `campaign:read`, same access and 404 body as the stuck-findings read) list live heavy attempts on a local provider with their reasons, detail and whether each fallback was explained. A heavy local attempt with no remote profile now raises the `heavy_stage_on_local` stuck finding as a configuration gap (`config_gap: no_remote_profile`, suggested `configure_a_salad_profile`) instead of staying silent. A stage refused before any attempt (`heavy_local_unexplained`, or a refuse-mode wait that ended without an attempt) carries a `placement.heavy_guard` block on its receipt entry. - Campaigns (ADR 0048): submit and approval refuse a stage whose grant lifetime is shorter than `max_duration_seconds` plus a 300 s margin (`grant_shorter_than_stage_duration`); the CPU `grant_ttl_seconds` bound rises to 43200. The runner issues a grant, and starts its lifetime, only when the project limits and a worker slot are free (`worker_slots`, 1-8, default 1, per `local_docker`/`self_hosted` entry; a grant whose launch the worker reported refused frees its slot at once, ADR 0046) (`campaign.stage_waiting_slot`), restarting the anchor at issue so waiting never shortens it. Expired grants whose operation has a confirmed exit and a recorded cost are reconciled automatically on the runner tick (`execution.expired_terminal_grant_reconciled`), never without that evidence and never from under an in-flight or unknown campaign attempt. - Campaigns (ADR 0053): the runner resolves an `admitted`, `running` or `unknown` attempt whose worker confirmed the exit with no contradicting observation. - Worker: the development worker renews a running operation's 30 s control lease on its first pass (including after recovery), then every 10 s of elapsed time as well as every 15 ticks, and never sleeps past the next renewal.
